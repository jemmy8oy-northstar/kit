# Longlist — the brief

_Written 2026-09-24 as the input to `behaviours/longlist.beh`. James,
[claude-code-bot#99](https://github.com/jemmy8oy-northstar/claude-code-bot/issues/99): **"you can
come up with your own projects. If you have any good ones I can create repos for you."** This is
mine. No repo, no routes, no source tree — so no locators exist to copy into `bindings.json`, which
is the condition the whole trial depends on._

## Why this one

His own ground rule (claude-code-bot#49) asks for ideas to be **captured** rather than started:
*"capture ideas when the creative brain is flowing, just don't let them become active build sprawl
(log to backlog, don't spin up PRs)."* The rule exists; the place does not. Today an idea lands in
one of three things that all mean something else — a private vault (a notebook, not a list), a
GitHub issue (which implies work has started), or this bot's board (mine, and pruned by design).

**Longlist is the missing fourth: a place whose entire point is "not yet a project".**

⚠️ **The honest weakness, stated up front.** It overlaps his vault, which already captures ideas
and is where he actually writes. The argument for building it anyway is that a vault note has no
*decision* attached, and the thing #49 is really asking for is not capture — it is a record of what
was decided and why. The argument against is that a fourth place to put an idea may just be a
fourth place to lose one. **That is his call, not mine, and it is the first question to answer.**

## <a id="capture"></a>Capture

Writing it down has to be cheaper than building it, or the rule loses to the instinct it is fighting.
One field, reachable from the list itself, no navigation. It asks for two things: **the idea, and
why it came up now** — the second because six weeks later the reason is the part that has
evaporated, and it is what makes the entry arguable rather than just a title.

An empty longlist says so rather than showing a blank page.

## <a id="decide"></a>Deciding

**An idea leaves the list by being decided, never by rotting.** Opening one shows why it was raised.
It can be taken forward, or declined — and **declining requires a reason**, which is the feature.
A longlist of undecided ideas is a to-do list with extra steps; a longlist of *declined* ideas with
reasons is the only version that teaches you anything about your own judgement.

## <a id="rot"></a>Not letting it rot

An idea nobody has decided on for a long time is visibly stale, and the oldest undecided idea sorts
to the top, so the list argues for attention rather than waiting for it.

## Deliberately not in scope

No sharing, no accounts, no notifications, no tags, no search. Every one of those is how a capture
tool becomes a project management tool, which is the failure mode this is supposed to prevent.
Storage is a file. It needs no database, no API key and no infrastructure that does not already
exist — which is also what makes it a candidate under his current pause on deployment work.
